# Примеры главы 14 руководства по RED

Глава 14 *RED Reference Manual* (Intermetrics, март 1979) описывает средства
нижнего уровня. Из этих операций построена параллельность высокого уровня из
главы 10, и из них же системный программист может построить свои планировщики
и механизмы синхронизации. Примеры главы переписаны в `original/` как
напечатаны, с ошибками, а `run/run.sh` делает их исполнимыми и запускает
компилятором redc, так же как `problems/` для контрольных заданий.

Каждый `run/*.sed` перечисляет правки, без которых транслятор не принял бы
текст, или заполняет то, что руководство оставило многоточием, с причиной
рядом с каждой строкой. `*-units.red` заменяют то, что пример считает уже
существующим, `*-head.red` и `*-main.red` встраивают пример в программу и
запускают его, `*.in` — то, что набирается на телетайпе, `*.out` — ожидаемый
вывод.

| Раздел | Пример | Что показывает запуск |
|---|---|---|
| 14.1.1 | Импульсные события: почтовый ящик длины 0 и `EMPTY_SLOTS` | три ждущих активации продолжают работу по одному сигналу; пришедшая позже ждёт следующего |
| 14.1.3 | Ответы через почтовый ящик, переданный в сообщении | десять отправителей, один получатель, каждый ответ доходит до своего отправителя |
| 14.1.4 | Прерывание клавиатуры через `LOCATION (INTERRUPT 16)` | набранные символы приходят по одному каждые 100 мс виртуального времени |
| 14.3.1 | `MAILBOX`, определённый средствами языка, с пользовательскими ожиданиями | заблокированный производитель, `WAIT` на определённом `receive` вместе с таймаутом, `cond_send`, `cond_receive` и счётчики слотов |
| 14.4.1 | Мониторы: `MONITOR_LOCK` и `MONITOR_QUEUE` из замков данных, буфер строки на них | семантика Хоара: `CONTINUE` сразу передаёт монитор разбуженной активации |
| 14.5.3 | Круговой планировщик как пользовательский планировщик | три активации получают процессор по очереди квантами по 10 мс |

## Источники и права

Примеры взяты из *RED Reference Manual* (Intermetrics, март 1979; на
документах RED стоит «Copyright © 1979 Intermetrics, Inc.») в перепечатке Мэри
Ван Деузен на iment.com, где код дан картинками. Здесь они переписаны для
изучения и сравнения.

## Ошибки в напечатанных примерах

- 14.5.3: у `REGION dlock;` точка с запятой на месте `DO`, а переменная
  планировщика названа `new`, зарезервированным словом.
- 14.4.1: компонент записи назван `external`, зарезервированным словом, а
  `delay` передаёт `mq.lock`, атрибут, то есть значение, в `VAR`-параметр
  процедуры `unlock`.
- 14.4.1 (использование): `full` читается раньше, чем ему что-то присвоено.
- 14.3.1: `SYNCH_SIGNAL` вместо `SYNC_SIGNAL`, дважды `m.v` вместо `m,v` и
  `NEEDS ::=` вместо `NEEDS :=`. Очереди ожидания объявлены как очереди
  фиктивных типов запросов, а хранят активации (`INSERT (m.squeue, ME)`,
  `FIRST (m.squeue) = ME`), и отмена убирает из очереди фиктивный запрос
  вместо своей активации.
- В 14.3.1 есть и ошибка, которую не поймает никакой транслятор:
  `receive_REVOKE` проверяет `SIZE(m.msg) < m.len`, условие, скопированное из
  `send_REVOKE`, хотя его собственному инварианту 1 нужно `0 < SIZE(m.msg)`.
  Запуск оставляет напечатанное условие.

## Примеры, которые не запускаются

- 14.1.2, производитель и потребитель с активным ожиданием. С приоритетами как
  напечатано (потребитель 20, производитель 10) потребитель крутится в
  `COND_RECEIVE`, и по правилам планирования из 14.2.3 производитель на одном
  процессоре не получает управления никогда. Если поменять приоритеты местами,
  крутиться станет производитель, как только ящик заполнится. Примеру нужен
  второй процессор; на машине redc он один, и программа зацикливается.
- 14.3.3, развёртка оператора `WAIT`, — это схема, по которой redc
  транслирует `WAIT` с пользовательскими ожиданиями, а не программа.
- 14.6, `LOW_IO` на IBM 360 (`SIO` и `TIO` со словом адреса канала по адресу
  72), написан для той машины. На машине redc `LOW_IO` работает с телетайпом
  (устройство 1) и контроллером прерываний (устройство 2).
