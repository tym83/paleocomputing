# YELLOW

Третий из четырёх проектов конкурса языков DoD-1 1978 года: *Preliminary Design Phase Report
and Language Specification* SRI International (февраль 1978), проект, которому было велено
переделать Pascal под Ironman. GREEN стал Ada, RED дошёл до финала, YELLOW и BLUE отсеяли в
1978-м. Здесь он восстановлен по отчёту, перепечатанному в DTIC ADB950587, так же, как RED и
GREEN в соседних каталогах.

| Каталог | Что там |
|---|---|
| `boot/` | Бутстрап на Python: переводит подмножество, на котором написан первый yellowc (только для genesis) |
| `yellowc/` | yellowc — транслятор YELLOW на YELLOW, файлы склеиваются по порядку имён; выдаёт C, который линкуется с `../rt` |
| `seed/` | `yellowc.c`: то, что последний yellowc сделал из себя |
| `genesis/` | первый yellowc и C, который он сделал из себя, — шаг от бутстрапа |
| `lib/prelude.yel` | стандартная прелюдия реализации (XIV.XIII.1): StandardImplementationPrelude, MathLibrary, TextIO |
| `tests/` | тесты с ожидаемым выводом; `*.err.yel` должны отвергаться с сообщением из `.out` |
| `corpus/` | программы учебника 1978 года в напечатанном виде, что о них говорит транслятор, вынужденные правки и прогоны (`corpus/CHANGES.md`) |
| `notes/yellow-digest.md` | язык в реконструкции, со ссылками на страницы и всеми решениями там, где отчёт неясен |
| `notes/yellow-os.md` | YELLOW в работе над THE и Kubernetes (`../os/*_yellow.yel`, `../kube/kube_yellow.yel`, `../labs/yellow/`): для чего в нём не нашлось слов и два места, где yellowc не дотягивал до отчёта (теперь исправлены) |

```sh
make fixpoint       # yellowc из seed дважды; C должен совпасть
make genesis        # первый шаг, от бутстрапа на Python
make test           # tests/run.sh
corpus/run.sh       # программы 1978 года
./yc prog.yel       # перевести программу (после прелюдии) и собрать
```

Нужны компилятор C, make, Python 3 (только для genesis) и perl (для таймаутов).

Как выглядит YELLOW: операторы Pascal, закрытые ENDIF, ENDWHILE, ENDFOR; модули Modula
(закрытые области с IMPORT и EXPORT, OPAQUE и TRANSPARENT), мониторы и сигналы; разделение
типов и представлений (`INTEGER` — тип, `INTEGER [1..10]` — его представление); перегрузка
только через `EXTENDS` и `REPLACES`; шаблоны модулей с подстановкой; исключения обрабатываются
поблочно, и PROPAGATE_EXCEPTION покидает блок, в котором стоит. У двух напечатанных символов
нет ASCII-формы: `≠` пишется `#`, `↑` — `^`.

Из пятнадцати программ учебника пять принимаются как напечатаны; остальные показывают огрехи
текста, который ни разу не проходил через транслятор, а три из компилирующихся работают
неправильно.

На YELLOW работают и программы операционных систем из `../os/` и `../kube/`: система THE
Дейкстры, Kubernetes поверх неё, управляющий цикл Kubernetes и три контрастные задачи —
на мониторах, сигналах и шаблонах модулей. В `../labs/yellow/` восемь упражнений на то, чем
этот язык особенен (`../labs/README.ru.md`).
