# Лабораторные: что умеет RED

Двенадцать коротких упражнений на RED — языке, который в 1979 году проиграл
конкурс DoD-1 языку GREEN. Каждое занимает 10–20 минут. Программы лежат в
`labs/red/`, а `labs/check.sh` говорит, выполнено ли задание: он переводит ваш
файл компилятором `build/redc`, запускает его и смотрит, что получилось.

```sh
make                         # собирает redc из семени и проверяет неподвижную точку
labs/check.sh 01 look        # запустить лабораторную 1 как есть
labs/check.sh 01 change      # проверить вашу правку в labs/red/01-capsule.red
git checkout labs/red        # начать заново
```

Задания идут по уровням серии: **посмотреть**, **изменить**, **сломать**,
**измерить** и **построить**. Часы в этих программах виртуальные, а планировщик
точно следует правилам RED. Каждый запуск печатает одно и то же, так что свой
вывод можно сравнить с чужим.

| № | Программа | Задание | Что должно получиться |
|---|---|---|---|
| 01 | `01-capsule.red` | **посмотреть**, затем **изменить**: добавить в капсулу `FUNC peek(READONLY s : stack) => INT`, экспортировать её и напечатать `"peek " & CNVT[STRING[ASCII]](peek(s))` | `peek 7` |
| | | **сломать**: написать `s.top := 0;` в `main` | Экспорт типа не экспортирует выбор его компонент (RM 8.2). Так в RED делается абстрактный тип, без секции `private` |
| 02 | `02-imports.red` | **сломать**: убрать `hits` из списка IMPORTS процедуры `hit` | Процедура — закрытая область (RM 3.5, 3.7). Внешняя переменная видна только после импорта |
| | | **изменить**: присвоить `limit` внутри `hit` | `limit` импортирована как READONLY |
| 03 | `03-mailbox.red` | **посмотреть**: производитель уходит на три сообщения вперёд. **изменить**: `CONST size := 0` | Почтовый ящик размера 0 — это рандеву: `send 2` идёт после `got 1` |
| | | **измерить**: попробовать размеры 1, 2, 5 | Насколько отправитель может забежать вперёд |
| 04 | `04-wait.red` | **изменить**: сделать отправителя медленнее, чем ждёт WAIT | Побеждает таймаут |
| | | **сломать**: ждать `SEND(m0, 1)` при `m0 : MAILBOX[INT](0)` | X_EMPTY_MAILBOX. Рационале запрещает такое, потому что оно может привести к взаимной блокировке (RM 10.5) |
| 05 | `05-region.red` | **посмотреть**: исключение внутри REGION всё равно освобождает замок. **сломать**: убрать GUARD | Рабочая задача погибает, `main` ждёт вечно, и рантайм сообщает, что все задачи стоят |
| 06 | `06-priority.red` | **посмотреть**: `c b a`. **изменить**: дать всем трём одинаковый приоритет | `a b c`: при равных приоритетах порядок FIFO (RM 10.2) |
| 07 | `07-generic.red` | **посмотреть**: `swap` получает экземпляр для INT и для STRING, и никто их не называет. **построить**: написать `GENERIC t : TYPE FUNC max(CONST a, b : t) => t`, вызвать с числами и со строками, напечатать `"max ..."` | По экземпляру на тип, созданному в точке вызова (RM 11.3) |
| 08 | `08-pairs.red` | **изменить**: поставить `crash_after` на другой номер запроса | Где бы ни погиб основной процесс, аудит сходится |
| | | **сломать**: в основном процессе поменять местами `SEND` контрольной точки (вместе с её `IF`) и `SEND` ответа, чтобы сбой пришёлся между ними | Аудит находит подтверждённый перевод, которого нет в книгах. Сумма при этом верна, так что на глаз ошибки не видно |
| 09 | `09-kube-ha.red` | **посмотреть**: основной API-сервер погибает посреди выкатки, а кластер всё равно приходит туда, куда должен | |
| | | **сломать**: удалить в `node_ctl` цикл выборки очереди | После переключения выселяются здоровые узлы |
| 10 | `red/redc/*.red` | **построить**: добавить встроенную функцию `MAX(a, b)` в `builtin` в `07-expr.red`, выполнить `make fixpoint` и перевести программу, печатающую `MAX(3, 7)` | Компилятор, написанный на RED, принимает вашу правку и воспроизводит сам себя |
| 11 | `problems/run/C1-matrix-vector.sed` | **сломать**: выбросить одну строку sed-скрипта и снова перевести образец 1979 года | Каждая строка — это ошибка в напечатанном в 1979 году тексте, которую транслятор не пропускает |
| 12 | `12-the.red` | **посмотреть**: система THE Дейкстры (1968) в пяти уровнях; три программы делят три страницы памяти через барабан | Ни один процесс не ждёт процесса выше себя, и общество доходит до конца |
| | | **изменить**: `CONST ncore := 8` | `drum transfers 0`: на каждый сегмент своя страница, и контроллеру сегментов барабан не нужен |
| | | **сломать**: поставить `report_dumps` в `TRUE`, чтобы контроллер сегментов (уровень 1) сообщал оператору о каждой выгрузке через интерпретатор сообщений (уровень 2) | Взаимная блокировка: интерпретатору нужен контроллер сегментов, чтобы прочитать свой словарь. Поэтому в THE консоль стоит выше барабана |

Лабораторная 10 проверяет вашу программу: `labs/check.sh 10 build myprog.red`.
Лабораторная 11 — пересобранный образец:

```sh
sed -f problems/run/C1-matrix-vector.sed problems/original/red/C1-matrix-vector.red \
  | sed -n '/^CAPSULE matrix_vector_package/,/^END CAPSULE/p' > /tmp/c1.red
cat problems/run/C1-main.red >> /tmp/c1.red
labs/check.sh 11 break /tmp/c1.red
```

Эталонные решения заданий «изменить», «сломать» и «построить» лежат в
`labs/solutions/`. `labs/verify.sh` проверяет сам проверяющий скрипт: каждое
решение должно проходить, а исходная программа без правки — нет. CI запускает
его в каждом пулреквесте.

## BLUE

Ещё семь упражнений, на BLUE — проекте SofTech 1978 года, который выбыл после
первого этапа (см. `../blue/`). Они показывают то, что есть в BLUE и нет у других
или есть в другом виде. Программы лежат в `labs/blue/`, номера начинаются с `b`, а
`labs/check.sh` переводит файлы `.blu` компилятором `blue/build/bluec`.

```sh
make -C blue fixpoint        # собирает bluec из семени и проверяет неподвижную точку
labs/check.sh b1 look        # запустить лабораторную B1 как есть
labs/check.sh b5 break       # проверить вашу правку в labs/blue/b5-region.blu
git checkout labs/blue       # начать заново
```

| № | Программа | Задание | Что должно получиться |
|---|---|---|---|
| b1 | `b1-enums.blu` | **посмотреть**: литерал `\GREEN` принадлежит двум типам и в каждом стоит на своём месте | `light number 2 and color number 3` |
| | | **изменить**: добавить `\FLASHING` в `LIGHT` и сделать так, чтобы `NEXT_LIGHT` вела к нему от `\AMBER` | `\FLASHING` в цикле |
| | | **сломать**: написать `IF S < \SPADES THEN ... END IF;` | У типа `UNORDERED` есть `=` и `<>`, и больше ничего (3.4.4.1) |
| b2 | `b2-generic.blu` | **посмотреть**: одна `SWAP` с `?T` вызывается для целых, строк и цветов; экземпляры никто не называет | `swapped: 1978 BLUE` |
| | | **построить**: написать `FUNCTION BIGGER (X, Y: ?T) RETURNS (T) WHERE T NEEDS (LESS_THAN_ (T, T) RETURNS (BOOLEAN))`, вызвать её для целых и цветов, напечатать `'bigger ...'` | Каждый экземпляр берёт `LESS_THAN_` там, откуда его вызвали (раздел 5) |
| | | **сломать**: `SWAP (# I, K);` | `?T` связывается первым аргументом, а второй к нему не подходит |
| b3 | `b3-imports.blu` | **сломать**: убрать `ROUTINES: (HIT)` из `PLAY` | `PLAY` вызывает `HIT`, значит, должна импортировать либо `HIT`, либо все переменные, которые `HIT` трогает (4.1.1). |
| | | **изменить**: присвоить `LIMIT` внутри `HIT` | `LIMIT` импортирована как входная, до `#` |
| b4 | `b4-rep.blu` | **посмотреть**: коды состояния устройства как тип `UNORDERED` с `REP ENUM_VAL_REP` | `register 0001 reads \BUSY` |
| | | **изменить**: добавить `\OFFLINE AS BIN '0100'` и прочитать из регистра `BIN '0100'` | `reads \OFFLINE` |
| | | **сломать**: вынести `S := [STATUS]$$(REGISTER);` из `SELECT OBJECT_MACHINE` | Биты становятся значением только в машинно-зависимой части (4.5.5.2) |
| b5 | `b5-region.blu` | **посмотреть**: рабочий 1 погибает, держа семафор `REGION`, и рабочий 2 проходит | Семафор отпустило завершение пути (3.11.1) |
| | | **сломать**: объявить `MUTEX` как `SEMAPHORE (SYNCH)` | Взаимная блокировка. Семафор `SYNCH` — это сигнал, а погибающий путь не должен рассылать ложные сигналы (J3.11-1) |
| | | **изменить**: обернуть работу в `BLOCK`, поймать `FAILED` после него внутри пути и сделать там `RELEASE` | Оба проходят, блок ничего не сигналит. Если поймать без `RELEASE`, путь завершится нормально и так и будет держать семафор: снова блокировка |
| b6 | `b6-the.blu` | **посмотреть**: THE на BLUE — тот же прогон, что `12-the.red`, но на собственных семафорах BLUE | Ни один процесс не ждёт процесса уровнем выше |
| | | **изменить**: `CONST NCORE: INTEGER := 8;` | `drum transfers 0` |
| | | **сломать**: поставить `REPORT_DUMPS` в `TRUE` | Взаимная блокировка. Вызов вверх с самого начала был записан в IMPORTS: `DUMP` (уровень 1) импортирует `TELL_OPERATOR` (уровень 2), потому что bluec проверяет и выключенный вызов |
| b7 | `b7-race.blu` | **посмотреть**: таймаут — это гонка двух путей, `GET` и `TIMER`, которые завершают друг друга через `TERMINATE` | `2 received` |
| | | **изменить**: `CONST TIMEOUT: INTEGER := 5;` | `no item for 5 ms` |
| | | **сломать**: убрать `PRIORITY 1` у `GET` | `1 still in the box`: `TIMER` срубил `GET`, когда тот уже взял жетон элемента, и элемент остался в ящике, откуда его не достанет ни один `RECEIVE`. Более высокий приоритет даёт `GET` выполниться раньше, чем `TIMER` успеет так сделать |

Решения лежат в `labs/solutions/b*.blu`, и `labs/verify.sh` проверяет их вместе с
решениями для RED.
