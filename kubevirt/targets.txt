# Машины, которые несёт образ virt-launcher: по строке на архитектуру.
#
# Образ один на все чужие архитектуры — семейство, а не «образ RISC5». Новая
# машина — это строка здесь (и её цель QEMU в дереве), а не новый образ,
# новый тег и новая настройка кластера.
#
# Отсюда читают:
#   kubevirt/Containerfile        --target-list для QEMU и какие qemu-system-*
#                                 класть в образ;
#   qemu/libvirt/patch_libvirt.py какие архитектуры вписать в libvirt;
#   kubevirt/check_image.sh       что каждый эмулятор в образе есть и отвечает,
#                                 а libvirt знает каждую архитектуру.
#
# Колонки:
#   арх.        имя архитектуры. Оно же имя цели QEMU (<арх.>-softmmu), имя
#               бинаря (qemu-system-<арх.>) и имя архитектуры в libvirt. Одно
#               имя на три места не случайно: libvirt не верит описанию домена
#               и спрашивает архитектуру у самого эмулятора (query-target), а
#               тот отвечает именем своей цели. Разойтись им нельзя.
#   бит         разрядность: 16, 32 или 64 (у Lilith слово в 16 бит).
#   порядок     порядок байтов: LE или BE.
#   машина      машина QEMU по умолчанию для этой архитектуры.
#   PCI         есть ли у машины шина PCI: yes или no. Для незнакомой
#               архитектуры libvirt считает, что есть, и требует контроллер,
#               которого может не быть (qemu/libvirt/README.md).
#   описание    до конца строки; уходит комментарием в перечень libvirt.
#
# арх.   бит  порядок  машина   PCI  описание
risc5    32   LE       oberon   no   Wirth RISC5 32 LE http://www.projectoberon.net/
