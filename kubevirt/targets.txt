# Machines carried by the virt-launcher image: one line per architecture.
#
# One image for all foreign architectures: a family, not "the RISC5 image". A
# new machine is a line here (plus its QEMU target in the tree), not a new
# image, a new tag and a new cluster setting.
#
# Read by:
#   kubevirt/Containerfile        --target-list for QEMU and which qemu-system-*
#                                 to put in the image;
#   qemu/libvirt/patch_libvirt.py which architectures to add to libvirt;
#   kubevirt/check_image.sh       that each emulator is in the image and
#                                 responds, and libvirt knows each architecture.
#
# Columns:
#   arch        architecture name. It is also the QEMU target name
#               (<arch>-softmmu), the binary name (qemu-system-<arch>) and the
#               architecture name in libvirt. One name in three places is no
#               accident: libvirt does not trust the domain description and
#               asks the emulator itself for the architecture (query-target),
#               which answers with its target name. They must not diverge.
#   bits        word size: 16, 32 or 64 (Lilith has a 16-bit word).
#   order       byte order: LE or BE.
#   machine     default QEMU machine for this architecture.
#   PCI         whether the machine has a PCI bus: yes or no. For an unfamiliar
#               architecture libvirt assumes it does and demands a controller
#               that may not exist (qemu/libvirt/README.md).
#   description to end of line; goes as a comment into the libvirt list.
#
# arch   bits order    machine  PCI  description
risc5    32   LE       oberon   no   Wirth RISC5 32 LE http://www.projectoberon.net/
