# OberonKube

Целый кластер Kube одним заказом. Kube — управляющая часть Kubernetes,
написанная на Обероне: деплойменты, наборы реплик, поды, планировщик,
хранилище на диске, выкатки. Его узлы — машины Оберона, такие же, как
OberonVM, и общаются они по радио Вирта, как в OberonAir.

```yaml
apiVersion: apps.cozystack.io/v1alpha1
kind: OberonKube
metadata:
  name: farm
spec:
  nodes: 3
  key: 00c0ffee00c0ffee
  deployments: web 4 Ticker; api 2 Ticker2
```

Заказ превращается в релизы собственных компонентов этого каталога: эфир
(`<релиз>-air`), управляющую машину (`<релиз>-plane`) и по машине на узел
(`<релиз>-node1`, `-node2`, ...). Каждой машине при старте сообщается её роль:
управляющая выполняет `Kube.Start`, `KubeNet.Serve` и деплойменты, каждый узел —
`KubeNet.Join`. Кластер собирается сам, набирать ничего не нужно. Удаление
OberonKube убирает все части.

| поле | по умолчанию | |
|---|---|---|
| `nodes` | `2` | от 1 до 8; каждая машина занимает ядро хоста, цикл Оберона не простаивает |
| `cluster` | `kube` | имя кластера, до 8 символов |
| `key` | пусто | до 16 шестнадцатеричных цифр; каждое сообщение в эфире подписано им. Пусто — ключ из нулей: командовать узлами сможет любой в эфире |
| `deployments` | пусто | `имя реплики модуль` через `;`, применяются при старте |
| `memory` | `128Mi` | у каждой машины |
| `storageClass` | `replicated` | позволяет разнести машины по разным хостам |

Образ пода — модуль Оберона на узлах; попробовать можно `Ticker` и `Ticker2`,
а `Ticker.Show` на узле показывает, как его поды считают секунды. Новые
деплойменты применяются на управляющей машине через VNC, например
`Kube.Apply web 6 Ticker2`, и `web` выкатывается на вторую версию по одному
поду. На узле работает до 10 подов. Источник истины — форма: её деплойменты
применяются при каждом старте управляющей машины (`Kube.Apply`), поэтому
изменённая форма вступает в силу при следующем перезапуске, а правка
деплоймента из формы через VNC живёт до него. Деплойменты, которых в форме
нет, сохраняются.

Деплойменты применяются при старте управляющей машины, пока ещё не все узлы
подключились, поэтому первые узлы могут получить их все: как и настоящий
планировщик, Kube не переносит работающие поды на узел, пришедший позже.

Как устроен Kube, что измерено и что ломалось по дороге, — в
`impl/kube/README.ru.md` репозитория.
